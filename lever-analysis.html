What "Intelligent Payload" Means

  • Root Cause Classification — fiber cut vs OLT vs ISP backbone vs power, using optical power, topology, ping patterns
  • Guided Next Step — "Dispatch technician to junction X" vs "Call ISP NOC at number Y" vs "Wait for power restoration"
  • Priority Signal — "This affects a customer who just called CS" or "This OLT has had 3 outages this week"
  • ISP Correlation — "5 partners on the same POP are down — this is ISP-level, don't touch anything"

But Verification Has a Different Role to Play

While verification LAG is fine, the system lacks proactive verification intelligence:

  • False positive detection — 97% of LOCAL TINY incidents have zero tickets and zero calls. Some may be detection artifacts, not real outages. Can we identify and suppress these?
  • Recurrence detection — if the same location has 5 outages in a week, the "fix" isn't holding. Flag chronic locations for infrastructure investment.
  • Recovery confirmation to partner — partner doesn't know if their fix worked. A "your outage is resolved, 100% devices back" message closes the loop.
Workstream Split
Four Parallel Projects
Each project maps to specific levers, can be built independently by one person + Claude Code, and stitches back via shared incident data model.
Project 1 — Person A

Drift Detection & Early Alert Engine

Levers: Time to Detect (drift), Time to Inform

Target: 83,635 MICRO→LOCAL drifting incidents (43% of all)

  • Build drift-detection logic — flag MICROs still active at 60/90/120 min that historically don't self-resolve
  • Design early partner alert for drifting incidents before they become LOCAL
  • Build severity upgrade predictor — which MICROs will drift? (features: device count trend, OLT history, time-of-day, partner profile)
  • False positive filter — use ticket/call overlay to identify detection artifacts (97% of TINY have zero customer signal)

Impact: If 30% of drifting MICROs get early signal → ~12,500 incidents/week resolve 16hr faster

Project 2 — Person B

Intelligent Payload: AI Root Cause & Action Agent

Levers: Intelligent Payload, Verification

Target: All alerted incidents — transform "X devices down" into "WHY + WHAT TO DO"

  • Root cause classifier — fiber cut / OLT / ISP backbone / power / device-level, using optical power, topology, ping patterns
  • Action generation engine — specific next step per root cause (dispatch tech / call ISP NOC / wait / restart)
  • ISP correlation detector — multi-partner same-POP pattern → "ISP issue, we're escalating, do nothing"
  • Verification intelligence — recurrence detection, false positive flagging, "your fix worked" confirmation

Impact: RCA accuracy >80%. Partners act on first alert instead of waiting/guessing. Target P50 LOCAL SMALL from 133m to <60m.

Project 3 — Person C

Escalation Engine & Night-time Handling

Levers: Time to Inform (escalation), Bandwidth Protection (night)

Target: Fix the dead escalation ladder + close the 7x night penalty

  • Fix T120/T240 pipeline — currently 0.3% fire rate. Make it 100% for unresolved incidents.
  • Night-time differentiated rules — tighter grace (30 min instead of 60), auto-escalation if no ACK
  • Morning burst queue — prioritized action list for overnight incidents when partners wake up
  • Partner ACK tracking — seen vs ignored vs acted. Dynamic grace based on partner response history.
  • Auto-ISP escalation for correlated multi-partner outages with evidence package

Impact: Night P50 from 431m to <120m. Escalation fire rate from 0.3% to 100%.

Project 4 — Person D

Partner Performance & Bandwidth Management

Levers: Bandwidth Protection, Verification (feedback loop)

Target: 422 chronic partners generating 69% of incidents

  • Partner scorecard — P50 recovery, ACK rate, grace resolution %, night penalty, vs city average
  • Incident bundling & triage — group partner's 20 daily incidents by root cause cluster, show prioritized queue
  • Tiered treatment engine — fast partners (P50 <60m) get standard flow; slow partners (P50 >4hr) get shorter grace + earlier escalation
  • Chronic pattern detection — same OLT/location recurring → flag for infrastructure investment, not just repeated alerts
  • Best-practice transfer — what do 111 fast partners do differently? Codify and push to slow partners.

Impact: Move the median partner P50 from 388m to <120m. Reduce chronic partner incident volume by identifying infra issues.
